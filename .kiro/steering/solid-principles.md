# SOLID 원칙 준수 가이드

모든 코드 작성 및 리팩토링 시 SOLID 원칙을 준수합니다.

## 원칙

### S — 단일 책임 원칙 (Single Responsibility Principle)
- 하나의 클래스/모듈/함수는 하나의 책임만 가진다
- 변경의 이유가 하나뿐이어야 한다
- 파일이 비대해지면 역할별로 분리한다

### O — 개방-폐쇄 원칙 (Open/Closed Principle)
- 확장에는 열려 있고, 수정에는 닫혀 있어야 한다
- 새 기능 추가 시 기존 코드를 수정하지 않고 확장할 수 있는 구조를 선호한다
- 하드코딩된 분기(if/elif 체인) 대신 매핑, 레지스트리, 전략 패턴을 활용한다

### L — 리스코프 치환 원칙 (Liskov Substitution Principle)
- 하위 타입은 상위 타입을 대체할 수 있어야 한다
- 인터페이스/프로토콜을 정의하고, 구현체가 계약을 준수하도록 한다

### I — 인터페이스 분리 원칙 (Interface Segregation Principle)
- 클라이언트가 사용하지 않는 메서드에 의존하지 않도록 한다
- 큰 인터페이스보다 작고 구체적인 인터페이스를 선호한다

### D — 의존성 역전 원칙 (Dependency Inversion Principle)
- 상위 모듈이 하위 모듈에 직접 의존하지 않는다
- 추상화(인터페이스/프로토콜)에 의존한다
- 의존성은 생성자 주입 또는 파라미터로 전달한다

## 적용 기준
- 새 코드 작성 시 위 원칙을 기본으로 따른다
- 리팩토링 시 위반 사항을 식별하고 개선한다
- 단, 과도한 추상화로 복잡성이 증가하는 경우 실용성을 우선한다
